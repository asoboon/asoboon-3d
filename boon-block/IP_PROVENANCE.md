# BOON BLOCK — IP / Provenance Record

## Purpose

This file records the current provenance policy for the BOON BLOCK puzzle implementation.
It is intended to make the release path auditable and to reduce accidental reuse of third-party protected expression.

This is a technical provenance record, not a legal opinion or a guarantee of non-infringement.

## Current release rule

The production puzzle data must be generated from BOON BLOCK's own mathematical rules:

- 8×8 board
- 12 free pentomino shapes: F, I, L, P, N, T, U, V, W, X, Y, Z
- one movable 2×2 CORE
- rotations and reflections allowed
- complete tilings only
- board rotations/reflections treated as the same solution for the 16,146-count database

No published solution table is used as runtime source data.

## Solution database provenance

`boon-block/solutions.js` is generated by:

`boon-block/generate_solutions.cpp`

The generator derives legal placements from the coordinate definitions of the 13 pieces and searches the board directly.

The generator does not import, parse, scrape, transcribe, or embed any third-party solution list, diagram collection, PDF, web page, or commercial puzzle answer database.

The generated database is accepted only when the build verifies:

- JavaScript syntax is valid
- `BOON_SOLUTIONS.length === 16146`
- `BOON_SOLUTION_COUNT === 16146`

The known number 16,146 is used as a verification target for the mathematical result, not as copied solution content.

## Symmetry handling

The generator removes duplicate board rotations/reflections using only the eight symmetries of a square (the D4 symmetry group).

The implementation chooses a canonical CORE placement and, only where residual square symmetry remains, a canonical F placement. The remainder of each board is solved from the BOON BLOCK piece definitions.

This is a mathematical implementation detail and is not dependent on a published answer ordering or category system.

## UI / presentation policy

BOON BLOCK must not copy third-party puzzle presentation or branding.

Do not import or reproduce:

- third-party packaging or product artwork
- third-party color schemes intended to identify a commercial product
- published answer-sheet layouts
- proprietary category labels or classifications
- third-party explanatory copy
- screenshots, diagrams, or illustrations from another product
- third-party source code unless separately reviewed and licensed

BOON BLOCK's UI, hint colors, CORE presentation, sounds, animations, labels, and interaction design should remain project-authored.

## Hint-system policy

Hints may analyze the independently generated BOON BLOCK solution database.

The current intended visual language is:

- cyan: current placement can remain on a valid route
- yellow: next piece / focus
- red-orange: placement that should be reconsidered
- translucent ghost: concrete candidate placement

These presentation rules are BOON BLOCK product design and are not derived from any third-party answer sheet.

## Important limitation

During early prototyping, public information was reviewed to confirm the known 16,146-solution result and general pentomino background.

Accordingly, this project does **not** claim a formal legal “clean-room” process.

The current production implementation is instead an **independent reimplementation from mathematical rules**, with no third-party solution database embedded in the current release source.

If a formal clean-room record is ever required for litigation, licensing, acquisition, or due diligence, use separate personnel and legal counsel to establish that process.

## Release checklist

Before shipping a BOON BLOCK build:

1. Generate `solutions.js` from the repository generator.
2. Verify the 16,146 count automatically.
3. Verify JavaScript syntax automatically.
4. Confirm no external answer files are bundled.
5. Confirm no third-party artwork, text, logos, or screenshots are bundled.
6. Review new names, logos, music, fonts, and purchased assets for their own licenses.
7. Preserve this provenance record with the release source.
